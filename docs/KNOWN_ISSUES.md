# Known Issues

This register tracks pilot-risk issues that are real in the current repo state. It is intentionally focused on release confidence, operator trust, and live-data truth rather than general cleanup.

## How to read this

- `P0` means release-blocking for a live pilot.
- `P1` means high risk for false confidence, broken operator flow, or hidden live-data failure.
- `P2` means important but usually recoverable with explicit operator gates.
- `P3` means mostly informational, but still worth tracking because it affects trust.

## Coverage gaps to keep in mind

- There is no automated end-to-end test that exercises a real external provider from fetch to booked job in one uninterrupted run.
- There is no dedicated stale-run watchdog command in the repo today.
- There is no automated release gate that rejects `mode=simulated` unless the operator explicitly reads the output and acts on it.
- The strongest safety checks are distributed across `check:production`, `operator-healthcheck`, `validate-integrations`, `proof:servpro`, and the scanner burst scripts, so the release reviewer has to look at the whole chain.
